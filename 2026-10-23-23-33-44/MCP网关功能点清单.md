# MCP 网关功能点清单

> 网关能力按职责切分为 11 项。切分原则：**一项一个职责，互不重叠**——
> 「你是谁」（鉴权）与「你能用什么」（授权）分开，「能力从哪来」（协议转换）与「别被玩坏」（注入防护）分开，
> 「现在怎么样」（监控）与「发生过什么」（日志）分开。
> 命名纪律：功能点名称一律 ≤ 4 个字。
>
> **不含「负载均衡」**：网关拿到的后端地址基本只有一个（K8s Service DNS 或注册中心给的单点），
> 多副本间的流量分摊由基础设施完成，网关不重复实现。`endpoints` 支持多地址仅作逃生通道（灰度 / 异构后端），不作为独立能力。

## 功能点总览

| # | 功能点 | 一句话职责 | 涵盖的具体能力 | 优先级与落地节奏 |
| --- | --- | --- | --- | --- |
| 1 | **注册发现** | 后端从哪来 | 服务注册、**上下线（`DISABLED` / 删地址）**、连接池。**不做心跳上报与主动探活**，健康状态是每个 Pod 内存里的运行期状态 | 高：M1 |
| 2 | **路由转发** | 请求往哪发、怎么改写 | 路由匹配、地址选址（跳过本 Pod 已熔断的地址）、前缀剥离、URL 重写、头处理、流式转发、协议探测 | 高：M1–M4 |
| 3 | **熔断降级** | 后端出事时怎么自保 | 失败计数熔断、**半开借真实请求试探恢复**、超时控制、幂等重试、舱壁隔离 | 中：M2 有基础版，M6 完善 |
| 4 | **集群限流** | 总量怎么卡住 | Redis+Lua 令牌桶（global/**sys**/tool 三档，无租户/用户维度；**配额单位统一 QPM、`DECIMAL(10,4)` 可小数**，令牌按浮点累加）、fail-open 降级 | 中：M5 |
| 5 | **入口鉴权** | 你是谁 | API Key 校验、**来源系统 `sys_code` 权威值解析**（不做租户/用户身份）、后端凭证注入、透传开关、**凭证明文随机串存储 + 最小权限/日志不入原文的补偿控制（7.1-C）** | 高：M5（上线前必做） |
| 6 | **工具授权** | 你能用什么工具 | **`mcp_gw_grant` 按系统授予**（管理员在库里配，不采信请求头）、服务侧工具上限、list+call 双重校验、工具/服务启停开关 | 高：M2 / M5 |
| 7 | **协议转换** | 能力从哪来 | OpenAPI→MCP、工具聚合与前缀去重、模板渲染、响应/错误加工、spec 同步 | 高：M3 |
| 8 | **注入防护** | 别被玩坏 | 参数校验、模板转义、出站 SSRF 管控、日志脱敏 | 高：贯穿 M2–M4 |
| 9 | **监控指标** | 现在跑得怎么样，按谁分类 | **三面全路由统一埋点 + `sys_code` 主维度指标**、告警规则、`/actuator/health` 依赖检查、`trace_id` 贯穿 | 高：随链路一同期上线（M2） |
| 10 | **调用日志** | 发生过什么（即审计） | L1 结构化调用日志（默认）+ L2 `mcp_gw_call_log` 异步落库（开关启用）、入参脱敏 | 低但不省略：先日志、后落库 |
| 11 | **配置管理** | 怎么改配置 | 后台 CRUD（**含给外部系统授予/收回工具权限**）、按 version 热更新、缓存刷新、版本灰度 | 中：M5–M6 |

> **为什么把监控与日志拆成两项**：两者定位与投入完全不同。监控是运行期刚需，没有指标等于盲跑，随链路一上线；
> 审计在本方案的定位就是**结构化调用日志**——不做独立审计系统，默认 L1 日志检索即可，L2 落库按需开启。
> **唯一不让步的红线**：被授权拒绝（DENIED）的调用必须留痕，这是排查越权与提示注入的唯一依据。

## 区分度说明（容易混淆的几对）

| 对比 | 边界 |
| --- | --- |
| 入口鉴权 vs 工具授权 | 前者判「调用者身份是否合法」（Key → `sys_code`），后者判「这个身份被授予了哪些工具」（`mcp_gw_grant`）。通过鉴权 ≠ 有权限用工具；授权由管理员在库里授予，**不是调用方在请求头里声明什么就有什么** |
| 熔断降级 vs 集群限流 | 熔断保护的是**后端**（后端慢/挂了就别打了，被动响应），限流保护的是**网关与配额**（调用方别打太多，主动配额） |
| 注册发现 vs 监控指标 | 前者是"登记了哪些后端、是否被停用"的事实，后者是聚合趋势与告警（整体跑得怎么样，含 `mcp_gw_upstream_health`） |
| 监控指标 vs 调用日志 | 前者回答「现在怎么样」（聚合值、可告警），后者回答「某次调用具体是什么」（明细、可回溯）；前者丢失单条上下文，后者不可聚合告警 |
| 入口鉴权 vs 监控指标 | 前者产出 `sys_code`（调用方身份）并写入上下文，后者**消费**它做分组维度；鉴权失败时身份未知，统一归 `unknown`，由单独的鉴权失败指标兜底 |
| 协议转换 vs 注入防护 | 前者让后端能力「能被模型用」，后者确保这个转换过程不被参数注入、不被用来打内网 |
| 注册发现 vs 熔断降级 | 前者管"登记没登记、停用没停用"（静态事实），后者管"最近调得通不通"（每个 Pod 内存里的动态计数） |
