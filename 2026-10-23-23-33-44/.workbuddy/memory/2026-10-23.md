## v2 二次调整（用户三点指令）
- **长会话方案定为 Redis 会话外置**（不选会话亲和）：自实现 McpServerTransportProvider 存 Redis + EventStore 支持 Last-Event-ID 断点续传；注意已建立的 SSE 流无法序列化，只能靠 EventStore 重放恢复。Redis 需哨兵/Cluster。
- **取消 `mcp_service_instance` 表**（对标 Higress 一层模型）：多实例地址下沉为 `mcp_service.endpoints` JSON 数组 `[{url,weight,status,fail_count,last_heartbeat}]`，单实例时只一个元素。理由：Higress 的 McpServer 只有一层，多实例 LB 交给 K8s Service/Nacos；拆表要多一套 CRUD/缓存聚合/级联，且服务级配置会冗余漂移。触发拆表的条件：实例数>20 或心跳乐观锁冲突频繁或需单实例独立审计。
- **限流改集群限流**：Redis（哨兵/Cluster）+ Lua 令牌桶为唯一事实源，禁止任何本地计数器参与限流判定（否则副本扩容静默放大配额）；三档 key：global/tenant/tool；Redis 不可用默认 fail-open + 告警，可按服务改 fail-closed。
